# ساختار جداول پایگاه داده BRS (Database Schema)

پایگاه داده SQLite در مسیر `data/brs.db` است (حالت WAL برای خواندن هم‌زمان داشبورد).
ساختار **فقط** از طریق مایگریشن‌های `database/migrations/` ساخته و تغییر داده می‌شود. نسخه فعلی در جدول
`schema_migrations` ثبت است (آخرین نسخه: **007**). پیش از اعمال مایگریشن روی دیتابیس دارای داده،
نسخه پشتیبان در `data/backups/` ساخته می‌شود. هر مایگریشن «همه یا هیچ» است (خودش و ثبتش در یک تراکنش) و
اثر انگشت فایل‌های اجراشده در `migration_checksums` نگه داشته می‌شود: **مایگریشن اجراشده هرگز ویرایش
نمی‌شود** (برنامه با پیام روشن متوقف می‌شود)؛ هر تغییر = فایل جدید با شماره بعدی.

| مایگریشن | محتوا |
| :--- | :--- |
| 001 | جداول پایه: symbols، daily_prices، snapshots، collection_log |
| 002 | data_sources، corporate_actions، market_calendar، intraday_trades، data_quality_metrics، experiments |
| 003 | features_daily، features_intraday |
| 004 | ستون‌های خام و متادیتای نسخه 0.4.x (قبلاً با ALTER دستی اضافه می‌شدند) |
| 005 | شناسه پایدار ins_code، ادغام نمادهای تکراری، اصلاح معنای ستون‌های قیمت، ۵ مظنه کامل، حقیقی/حقوقی روزانه، کدال و قضاوت‌های هوش مصنوعی |
| 006 | ایندکس‌های پرس‌وجوی مقطعی (تاریخ) برای نبض بازار و فیچرهای بازار |
| 007 | دفتر اصلاحات: `daily_prices_revisions` و `client_types_daily_revisions` — اگر TSETMC عددی از گذشته را تغییر دهد، مقدار قبلی (با زمان دریافت قبلی و زمان جایگزینی) حفظ می‌شود. فقط تغییر واقعی ثبت می‌شود؛ کپی اولیه از کل داده گرفته نمی‌شود |

## ۱. `symbols` — نمادها
| ستون | نوع | توضیحات |
| :--- | :--- | :--- |
| `id` | INTEGER PK | شناسه داخلی |
| `ins_code` | TEXT UNIQUE | **شناسه پایدار نماد در TSETMC** (insCode) — کلید اصلی هویت |
| `symbol_fa` | TEXT UNIQUE | نماد فارسی یکسان‌سازی‌شده (ی/ک فارسی) |
| `tse_code` | TEXT UNIQUE | کد ISIN (مانند IRO1FOLD0001) |
| `name_fa` | TEXT | نام شرکت |
| `market` | TEXT | `bourse`، `farabourse` یا `farabourse_base` |
| `flow` | INTEGER | کد بازار TSETMC: 1 بورس، 2 فرابورس، 4 پایه |
| `instrument_type_code` | INTEGER | yVal: 300 سهام بورس، 303 سهام فرابورس، 309 پایه، 313 SME |
| `board_code` | TEXT | کد تابلو (N1، N2، Z1، 1Z، ...) |
| `sector_code`، `sector_name` | TEXT | صنعت |
| `shares_outstanding` | REAL | تعداد سهام |
| `base_volume` | INTEGER | حجم مبنا |
| `is_active`، `status` | | نمادی که دیگر در بازار نیست غیرفعال می‌شود ولی داده‌اش حذف نمی‌شود |
| `created_at`، `updated_at`، `last_seen_at` | TEXT | زمان‌ها (تهران) |

## ۲. `daily_prices` — کندل روزانه (Point-in-Time)
| ستون | نوع | توضیحات | در فیچر |
| :--- | :--- | :--- | :---: |
| `symbol_id`، `date` | | `UNIQUE(symbol_id, date, source)` | |
| `open_raw` | REAL | اولین معامله روز (TSETMC: priceFirst) | ✅ |
| `high_raw`، `low_raw` | REAL | بیشترین/کمترین معامله | ✅ |
| `close_raw` | REAL | **آخرین معامله** (pDrCotVal) | ✅ |
| `close_final_raw` | REAL | **قیمت پایانی رسمی** (pClosing) — مبنای دامنه نوسان روز بعد | ✅ |
| `ref_price_raw` | REAL | **قیمت مرجع روز** (priceYesterday) — در روز اقدام شرکتی تعدیل‌شده | ✅ |
| `volume`، `value`، `trade_count` | | حجم، ارزش (ریال)، تعداد معاملات | ✅ |
| `adjustment_factor` | REAL | ضریب اقدام شرکتی همان روز = مرجع ÷ پایانی روز قبل (روز عادی = ۱) | ❌ |
| `adj_close` | REAL | قیمت پایانی تعدیل‌شده رو به عقب — **فقط نمودار** | ❌ |
| `open`، `high`، `low`، `close` | REAL | ستون‌های قدیمی (برابر *_raw) برای سازگاری | — |
| `source` | TEXT | `tsetmc` | |

- روزهای بدون معامله (توقف نماد) کندل ندارند.
- اگر فقط قیمت اولین/آخرین معامله با بازه روز ناسازگار باشد، همان فیلد خالی (NULL) می‌شود و روز حفظ می‌شود.
- **تاریخچه نسخه‌های قبل:** تا نسخه 0.4.2، ستون `adj_close` در واقع قیمت پایانی رسمی خام بود. مایگریشن 005 آن را به `close_final_raw` منتقل کرد.

## ۳. `client_types_daily` — حقیقی/حقوقی روزانه
`buy_i_*` = خرید حقیقی، `buy_n_*` = خرید حقوقی، `sell_i_*` و `sell_n_*` = فروش؛ هر کدام `volume`، `value` (ریال) و `count`.
`UNIQUE(symbol_id, date)`.

## ۴. `snapshots` — اسنپ‌شات لحظه‌ای تابلو
| گروه | ستون‌ها |
| :--- | :--- |
| زمان | `captured_at` (تهران، زمان ثبت محلی)، `provider_timestamp` (زمان سرور)، `last_trade_time` |
| قیمت | `last_price`، `close_price`، `open_price`، `high_price`، `low_price`، `ref_price` |
| دامنه نوسان | `price_limit_up`، `price_limit_down` |
| دفتر سفارش | `bid_price_n`، `bid_vol_n`، `bid_count_n`، `ask_price_n`، `ask_vol_n`، `ask_count_n` برای n = ۱ تا ۵ |
| صف | `buy_queue_volume` (حجم تقاضا وقتی بهترین تقاضا روی سقف است)، `sell_queue_volume` (قرینه) |
| حقیقی/حقوقی تجمعی امروز | `real_buy_volume/count`، `real_sell_*`، `legal_buy_*`، `legal_sell_*` |
| معاملات تجمعی | `volume`، `value`، `trade_count`، `base_volume` |

اسنپ‌شاتی که نسبت به ثبت قبلی همان نماد تغییری نکرده، ذخیره نمی‌شود.

## ۵. `announcements` — اطلاعیه‌های کدال
`tracing_no` (یکتا)، `symbol_fa`، `company_name`، `title`، `letter_code`، `sent_at`، `published_at` (تهران)، `url`.

## ۶. `announcement_judgments` — قضاوت هوش مصنوعی
`announcement_id`، `model` (مثلاً jev-1.13.0)، `questions_version`، `category`، `category_confidence`،
`impact_score` (۰ = به‌شدت منفی تا ۴ = به‌شدت مثبت)، `impact_confidence`، `is_material` (احتمال ۰ تا ۱)،
`answers_json`، `input_tokens`. `UNIQUE(announcement_id, model, questions_version)`.

## ۸. میز کار شخصی — مایگریشن 008

- `personal_profile`: سرمایه مبنا و سقف زیان کل به ریال صحیح، تأیید کامل بودن دفتر واقعی و زمان تهران؛ فقط ردیف id=1.
- `trade_plans`: برنامه دستی کاربر با نماد، افق، نوع دفتر، تعداد، ورود/سناریوی حد زیان/هدف به ریال، دلیل و JSON محاسبه با نسخه و هزینه‌ها.
- `journal_executions`: اجراهای گزارش‌شده دستی با نوع دفتر `paper` یا `actual`، سمت خرید/فروش، تعداد، قیمت و کارمزد ریالی، منشأ کارمزد، زمان اجرا/ثبت و دلیل. شناسه اجرای یکتا برای ثبت تکرارپذیر و `plan_id` اختیاری.
- این داده‌ها رکورد بازار نیستند و در قیمت‌ها/فیچرهای پژوهش وارد نمی‌شوند. دفتر کاغذی به عنوان اجرای واقعی نمایش داده نمی‌شود.
- اجراها append-only هستند؛ UPDATE/DELETE با trigger رد می‌شود. اصلاح اشتباه، واریز/برداشت و تغییر موجودی ناشی از اقدام شرکتی هنوز ابزار اختصاصی ندارند؛ در چنین شرایطی دفتر واقعی کامل تلقی نمی‌شود.
- نوشتن اجرا با `BEGIN IMMEDIATE` و کنترل موجودی/نقدینگی در همان تراکنش انجام می‌شود؛ فروش جزئی با بهای میانگین موزون و سهم کارمزد خرید محاسبه می‌شود.
- نسخه پشتیبان پیش از ارتقای دیتابیس دارای داده ساخته می‌شود. مایگریشن‌های 001 تا 007 تغییر نکرده‌اند.
- دو پاسخ متفاوت اسنپ‌شات با ساعت دریافت کاملاً یکسان، رکورد همان لحظه را به آخرین پاسخ واقعی به‌روزرسانی می‌کنند؛ زمان ساختگی افزوده نمی‌شود. پاسخ کاملاً یکسان همچنان نادیده گرفته می‌شود.

## ۹. گزارش خصوصی کارگزاری — مایگریشن 009

- `broker_imports`: نوع `portfolio`، `turnover` یا `fills` (نام داخلی برای ردیف معاملات خروجی سابقه سفارشات)، SHA-256 فایل خام، نسخه parser، زمان برداشت و ورود تهران، نام فایل و JSON فراداده. کلید نوع/اثر انگشت/نسخه از ثبت تکراری همان فایل جلوگیری می‌کند.
- `broker_records`: JSON هر ردیف با ترتیب اصلی و کلید `(import_id, ordinal)`. دو ردیف ظاهراً برابر حذف نمی‌شوند؛ گزارش شناسه یکتای اجرای بورس ندارد.
- `broker_baselines`: مبنای صریح مرحله، سقف زیان صحیح ریالی، زمان پذیرش و شناسه سبد منبع. ورود گزارش جدید مبنا را تغییر نمی‌دهد؛ جدول‌ها append-only هستند.
- آخرین گزارش هر نوع بر اساس زمان برداشت/ورود انتخاب می‌شود؛ فایل‌های هم‌پوشان با هم جمع نمی‌شوند. ورود هر فایل تراکنش مستقل دارد.
- parser گردش حساب مانده ابتدای دوره و زنجیره تک‌تک بدهکار/بستانکارها را کنترل می‌کند؛ علامت بدهکار در خروجی XLSX منفی است. مبالغ قیمت/کارمزد گزارش عیناً حفظ می‌شوند و با نرخ هزینه تنظیمات جایگزین نمی‌شوند.
- `fills` اجرای خودکار دفتر واقعی نیست؛ گزارش‌ها هیچ ردیفی در `journal_executions` یا داده بازار نمی‌سازند. کامل بودن دفتر واقعی پس از ورود سبد تا بازسازی موجودی مسدود است. مبنای پذیرفته‌شده از فرم عادی تنظیمات قابل تغییر نیست.
- تغییر parser با نسخه جدید، یک ورود تازه می‌سازد و ورود قبلی را بازنویسی نمی‌کند. مایگریشن‌های اعمال‌شده قبلی تغییر نکرده‌اند.

## ۱۰. قیمت عمومی برای تطبیق تمام دارایی‌ها — مایگریشن 010

- `account_market_observations`: نماد، شناسه TSETMC، زمان مشاهده تهران و JSON قیمت خام/تاریخ/نوع ابزار/منبع عمومی؛ append-only.
- برای ارزش‌سنجی دارایی‌های خارج از دامنه پژوهش مثل حق‌تقدم، بازار پایه و SME است. این جدول در جامعه سهام، فیچر یا بکتست مصرف نمی‌شود.
- دکمه دریافت قیمت عمومی یا فرمان `broker-refresh-quotes` از قرارداد `BaseDataProvider` استفاده می‌کند؛ همه دارایی‌های واردشده را در همین جدول مستقل تازه می‌کند و جامعه پژوهش/قیمت‌های اصلی را تغییر نمی‌دهد. خطا، مشاهده معتبر قبلی را حذف نمی‌کند. اصلاح همان تاریخ با زمان مشاهده منبع مقایسه می‌شود تا قیمت قدیمی روی اصلاح جدید ننشیند.
- گزارش حساب آخرین قیمت موجود از آرشیو اصلی یا مشاهده عمومی را مقایسه می‌کند. میدان مقایسه `close_raw` یعنی آخرین معامله است، نه `close_final_raw` یعنی پایانی رسمی. برابری عدد بدون تاریخ جلسه بازار، تطبیق هم‌زمانی کامل تلقی نمی‌شود.
- همه فایل‌های خام و گزارش‌های مشتق در `data/private/` هستند و طبق `.gitignore` منتشر نمی‌شوند. پشتیبان خودکار پیش از مایگریشن دیتابیس دارای داده برقرار است.
