# BRS 0.7.52 — تحویل میز محلی و زیرساخت پژوهش

این نسخه، کد پژوهش و پایش شخصی را یکپارچه می‌کند. عنوان «پایدار» به قراردادهای نرم‌افزار و
کنترل‌های انتشار مربوط است؛ راهبرد معاملاتی پذیرفته‌شده، سود تضمین‌شده، پوشش کامل تاریخ بازار
یا تأیید اجرای سفارش از آن نتیجه نمی‌شود. برنامه سفارش کارگزاری ارسال نمی‌کند.

## تغییرات این نسخه

- بکتست قواعد موجود با نقد مشترک، دفتر اجرای قابل بازبینی، هزینه، ظرفیت، صف و نتایج نامعلوم؛
  [دامنهٔ ماتریس و بازپخش](../research/strategy-suite-fa.md).
- دفتر شواهد افزایش سرمایه، حق‌تقدم و مطالبات با تفکیک سهم، نقد و حقِ هنوز وصول/آزاد نشده؛
  [قرارداد حسابداری](../research/documented-capital-claims-fa.md) و
  [فروش حق بدون پول اضافه](../research/rights-disposal-fa.md).
- ثبت تلاش‌های پژوهش، بودجهٔ محاسبه و checkpoint؛ حذف کار تکراری، به معنی شاهد مستقل تازه نیست.
  [کنترل جست‌وجو](../research/backtest-search-foundation-fa.md).
- مسیر اختیاری CPU برای Ridge و Q-learning با همان موتور سبد، پذیرش داده قبل از fit و
  بازسازی فیچر/scaler از خام؛ [نصب و قرارداد ML/RL](../research/ml-rl-compute-foundation-fa.md).
- فیلترهای دسته‌ای با منطق درست/غلط/نامعلوم و یکتاسازی ریاضی؛
  [راهنمای فیلتر](../research/three-valued-rule-space-fa.md).
- نواحی حمایت/مقاومت توصیفی، نسخه‌بندی خبرهای مجمع و نشانگر صریح آمادگی در مرکز فرمان؛
  [حمایت و مقاومت](../research/price-levels-fa.md)، [داشبورد](../unified-dashboard-fa.md).
- محافظت از ردیف‌های بومی آخرین جلسه در برابر بازنویسی تاریخچهٔ قدیمی و حفظ قرارداد آرشیو؛
  [انتشار روزانه](../daily-publications-fa.md). هویت دقیق تولیدکنندهٔ پیش از انتشار نیز با همان
  decoder و وابستگی‌های عددی تأییدشده خوانده می‌شود؛ نسخهٔ قدیمی بازنویسی یا retag نمی‌شود.
- اصلاح وابستگی‌های آسیب‌پذیر certifi و Pillow با ارتقای سازگار Streamlit و حفظ نسخه‌های
  محاسباتی؛ [یافته‌ها، منابع اصلی و حدود بررسی امنیتی](../reviews/2026-11-14-dependency-security-fa.md).
- آزمون‌های رگرسیون زمان تصمیم، بودجهٔ خرید، عواید فروش، صف پایانی و مقدار نامعلوم؛ بررسی‌های
  خارجی [v4](../reviews/2026-11-14-tse-v4-comparison-fa.md)،
  [v6](../reviews/2026-11-14-tse-v6-followup-fa.md) و
  [v7](../reviews/2026-11-14-tse-v7-followup-fa.md) به‌عنوان شواهد محدود نگه داشته شده‌اند.
- ابزار عمومی ساعت/زمان‌بندی دستی ویندوز با رسید محلی و حالت rehearsal؛
  [دامنه و محدودیت‌های ابزار](../manual-timing-clock.fa.md). آزمون‌های بدون ورودی دسکتاپ در CI
  ویندوز اجرا می‌شوند؛ این‌ها زمان پذیرش کارگزاری یا هسته را اندازه نمی‌گیرند.

## نصب و اجرا روی ویندوز

از ریشهٔ checkout یا ZIP همین نسخه، با Python 3.11:

```powershell
.\SETUP.bat
.\START.bat
```

`SETUP.bat` محیط پایه را با `requirements.lock.txt` هماهنگ می‌کند. Node/Playwright لازم برای
دریافت فقط‌خواندنی فارابی جدا نصب می‌شوند:

```powershell
.\SETUP_FARABI.bat
.\CAPTURE_FARABI.bat --check
.\WATCH_FARABI.bat --check
```

فرمان‌های `--check` بررسی نصب‌اند و به حساب وارد نمی‌شوند. برای برداشت واقعی فقط‌خواندنی،
راهنمای فارابی حاکم است؛ رمز، OTP یا توکن را در Git قرار ندهید.

نصب پروفایل اختیاری آموزش CPU:

```powershell
.\venv\Scripts\python.exe -m pip install --require-hashes -r requirements-training.lock.txt -c requirements.lock.txt
.\venv\Scripts\python.exe -m pip check
.\venv\Scripts\python.exe -m research.learning --help
.\venv\Scripts\python.exe -m research.rule_space --help
```

Torch، CUDA، TPU و آموزش توزیع‌شده جزو پروفایل تأییدشدهٔ این انتشار نیستند. راهنمای ML/RL
حد ورودی، منابع، نقش‌های train/validation/test و شرط افزایش محاسبات را توضیح می‌دهد.

## ارتقا و بازیابی

دادهٔ کاربر در `data/` و گزارش‌ها در `data/private/` محلی‌اند و در مخزن عمومی نیستند. پیش از
جابه‌جایی نصب، نسخهٔ پشتیبان محلی را حفظ کنید. مهاجرت ۰۱۷، جدول‌های مستقل دفتر جست‌وجو را
ایجاد می‌کند؛ migrationهای قبلی تغییر نکرده‌اند و مدیر دیتابیس پیش از ارتقای داده‌دار backup
می‌سازد. schema جدید را با نسخهٔ قدیمی برنامه اجرا نکنید؛ برای بازگشت به نسخهٔ قدیمی از backup
متناسب همان schema استفاده کنید.

فایل‌های پژوهش قدیمی بازنویسی یا retag نمی‌شوند. قرارداد جاری بستهٔ یادگیری
`causal-learning-bundle-v2` است؛ بستهٔ v1 با تغییر نام سازگار نمی‌شود. هویت کد، محیط، هزینه و
داده در پذیرش کنترل می‌شود؛ تغییر نسخه می‌تواند به ساخت بستهٔ تازه از خام یا اجرای runtime
محفوظ همان مطالعه نیاز داشته باشد. این رفتار، شکست سودآوری مدل محسوب نمی‌شود. پروتکل ABAN07
و دوره‌ای که قبلاً دیده شده، با انتشار کد دوباره «آزمون مستقل» نمی‌شوند.

## کنترل‌های انتشار

حداقل لازم پیش از commit:

```powershell
.\venv\Scripts\python.exe -m pytest tests/ -m "not network"
.\venv\Scripts\ruff.exe check .
.\venv\Scripts\python.exe -m pip check
```

برای رسید کامل با فهرست آزمون‌ها، تشخیص تکرار/مفقودی و hash قبل/بعد منابع، از
`python -m ops.validation_run --help` استفاده کنید؛ پوشهٔ خروجی باید تازه و زیر `data/private/`
باشد. CI همین snapshot را روی Windows و Ubuntu، همراه پروفایل اختیاری CPU، آزمون‌های Node و
کنترل‌های نصب ویندوز اجرا می‌کند. لینک commit/CI و نتیجهٔ واقعی اجرای انتشار ملاک است؛ صرف
وجود این دستورها یا badge، موفقیت اجرای تازه را اثبات نمی‌کند.

علت skip محلی، نداشتن مجوز ایجاد symlink در Windows بود؛ آن آزمون موفق شمرده نشد. چهار
آزمون شبکه در نتیجهٔ آفلاین حضور ندارند. نتایج CI مستقل Windows/Ubuntu در Checks مربوط به
commit انتشار دیده می‌شوند؛ جدول بالا فقط اجرای محلی است.

اجرای پیش از اصلاح وابستگی‌های امنیتی، عمداً متوقف و ناقص نگه داشته شد؛ شمارهای بالا فقط
مربوط به اجرای کامل با قفل اصلاح‌شده‌اند. رسیدهای کامل و گزارش حساب خصوصی در `data/private/`
محلی باقی ماندند. بررسی doctor نهایی خطای نصب نداشت، ولی تازگی دادهٔ محلی هشدار داشت؛
آمادگی داده و پذیرش روش معاملاتی از موفقیت آزمون‌ها نتیجه نمی‌شود.

## حدود باقی‌مانده

- نبود یا نقص دادهٔ تاریخی، عضویت جامعه در زمان تصمیم و حقوق شرکتی می‌تواند مطالعه را نامعلوم
  کند. hash و آزمون واحد، اصالت و کامل‌بودن منبع را ثابت نمی‌کنند.
- صف، توقف، تأخیر هشدار و ظرفیت، اجرای واقعی را محدود می‌کنند؛ mark روزانه وجه نقد نیست.
- یافته‌های فعلی، روش سوددهٔ پذیرفته‌شده‌ای برای پول واقعی معرفی نمی‌کنند. اهداف بازده و ریسک
  به‌عنوان هدف ارزیابی باقی می‌مانند و نتیجهٔ نرسیدن به هدف باید گزارش شود.
- اتصال زندهٔ کارگزاری، دریافت CAPTCHA، تحویل صدای هشدار روی دستگاه کاربر و پذیرش هسته از
  آزمون‌های آفلاین نتیجه نمی‌شوند؛ وضعیت هرکدام باید با شاهد همان جلسه مشخص شود.
