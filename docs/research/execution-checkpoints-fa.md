# ازسرگیری بازپخش تصمیم‌های محفوظ با checkpoint

این مسیر، شواهد بومی را روی همان تصمیم‌های محفوظ SUITE بازاجرا می‌کند؛ مدل یا استراتژی تازه آموزش نمی‌دهد.
هدف، تکرارنکردن برش‌های کامل‌شده پس از قطع اجراست. محدودیت‌های اقتصادی و مطالبات نامعلوم منبع پابرجا هستند.

## استفاده

```powershell
.\venv\Scripts\python.exe brs.py strategy-suite --from-suite "data/private/.../SUITE-..." --resolve-publications "data/private/.../publications.json" --workers 2
```

برای پایلوت محدود، `--case` و `--fold` تکرارپذیرند؛ مثلاً `--case cash --case base:momentum_5d:h1 --fold 3 --fold 4 --max-replays 8`.
شمارهٔ fold صفرمبناست و باید مرتب و یکتا باشد. نام قواعد پیش از ثبت به ترتیب اصلی کاتالوگ برمی‌گردند؛
زیرمجموعهٔ قواعد/برش‌ها جزو هویت قرارداد و cache است. داده، فیچر و تصمیم والد دوباره انتخاب یا آموزش داده
نمی‌شوند. دامنه باید پیش از نتیجه تعیین شود؛ حذف برش نامعلوم یا زیان‌ده پس از نتیجه، پژوهش معتبر نمی‌سازد.

دفتر تلاش‌ها پیش از بازپخش ثبت می‌کند. برای تکرار صریح اجرای پایان‌یافته یا قطعِ ثبت‌شده، `--allow-repeat` لازم است.
سیاست یکتا تازه محسوب نمی‌شود؛ تلاش تازه ثبت می‌شود. اجرای ناتمام همچنان مسدود است. در قطع سخت، پس از
بررسی مستقل پایان پردازش می‌توان رسید `local_search_registration` محفوظ در protocol را با API
`finish_trials(..., status='interrupted', evidence=...)` تعیین تکلیف کرد. این ابزار مرگ پردازش را خودکار تشخیص
نمی‌دهد و فایل نتیجهٔ نیمه‌کاره را بازنویسی نمی‌کند.

`--no-cache` محاسبه را بدون خواندن یا نوشتن checkpoint اجرا می‌کند. `--review ... --reexecute` نیز همواره
بازپخش مالی بدون cache انجام می‌دهد. شمار hit/miss، تله‌متری اعلام‌شده است؛ بازپخش سرد تاریخچهٔ آن را اثبات نمی‌کند.

## قرارداد، انتشار و فضا

- کلید شامل manifest والد، بایت انتشار بومی، کد، محیط وابستگی، کارمزد، مرز مهروموم و شمارهٔ برش است.
  manifest والد، تقویم، داده، سرمایه، قواعد و تصمیم‌های اصلی را مقید می‌کند. worker و شناسهٔ اجرای تازه
  کلید مالی تازه نمی‌سازند. تغییر ورودی یا قرارداد باعث می‌شود checkpoint قبلی مصرف نشود.
- منبع، ورودی‌ها، کارمزد و محیط قبل و پس از محاسبه کنترل می‌شوند. هر checkpoint تمام قواعد و سناریوهای
  یک برش و رسیدهای حسابرسی آن‌هاست؛ نیمهٔ یک حساب یا یک معامله به‌تنهایی ذخیرهٔ قابل ادامه نمی‌شود.
- ZIP تک‌فایلی فقط پس از تکمیل، کنترل شمار اعضا و hash و fsync به‌طور اتمی منتشر می‌شود. توقف پیش از
  انتشار، cache معتبر نمی‌سازد. ورودی خراب نه صفر می‌شود و نه بی‌سروصدا بازنویسی و محاسبهٔ مجدد می‌شود.
- قفل بومی سیستم‌عامل، محاسبهٔ هم‌زمان همان کلید را رد می‌کند و با مرگ پردازش آزاد می‌شود. فایل یک‌بایتی
  lock ممکن است باقی بماند؛ وجود فایل، شاهد اجرای زنده نیست. انتشار کلیدهای متفاوت هم با قفل کوتاه هماهنگ است.
- محل محلی `data/private/research-cache/execution-folds` است. سقف پیش‌فرض ZIPهای آن ۲ گیگابایت، حداکثر
  هر عضو ۳۲ مگابایت و مجموع بازشدهٔ هر checkpoint ۵۱۲ مگابایت است. این سقف شامل فایل موقت، حافظه،
  آرشیو اصلی یا کل دیسک نیست. اندازهٔ دقیق خروجی آینده پیش از محاسبه معلوم نیست؛ هنگام انتشار نیز سقف
  دوباره کنترل می‌شود. حذف/eviction خودکار یا بازنویسی checkpoint خراب انجام نمی‌شود.

## صحت و حدود ادعا

بازپخش تک‌پردازشی، موازی، ازسرگرفته و بدون cache باید JSONهای مالی یکسان تولید کنند. آزمون‌ها قطع بعد از
یک برش، خرابی hash، عضو اضافی/مفقود/تکراری، تغییر قرارداد و شکست انتشار را می‌آزمایند. خطای محاسبه یا
cache، رأی مالی علیه روش نیست.

cache محلی، شاهد مستقل نیست. بازنویسی سازگار همهٔ محتوا و hashهای داخلی، با hash خوداظهاری به‌تنهایی
رد نمی‌شود؛ بازپخش مالی بدون cache همچنان کنترل مستقل لازم است. این قابلیت، کالیبراسیون آماری، حل حقوق
اقدامات شرکتی یا پذیرش برای معامله را اثبات نمی‌کند.

دفتر اکنون SUITE و بازپخش شواهد بومی را پوشش می‌دهد؛ سایر workflowها باید صریحاً متصل شوند. کامل‌شدن
این مسیر مجوز جست‌وجوی تطبیقی روی holdout یا اجرای میلیون‌ها استراتژی نامرتبط نیست.
