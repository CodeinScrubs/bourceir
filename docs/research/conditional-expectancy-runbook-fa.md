# اجرای پژوهش بازده شرطی در Windows

دستورها برای BRS۰٫۷٫۲۹ هستند؛ patch بیرونیِ پایه۰٫۷٫۲۶ را دوباره اعمال نکنید.
وابستگی و migration تازه نداریم. این دو فرمان ماژولی، فایل‌های دریافت زنده را تغییر نمی‌دهند؛
پایلوت منبع قیمت می‌تواند با کد محفوظ خودش ادامه یابد. هیچ سفارش کارگزاری ارسال نمی‌شود.

## ورودی و آزمون

ابتدا آزمون‌های آفلاین و Ruff باید موفق باشند:

```powershell
.\venv\Scripts\python.exe -X utf8 -m pytest -m "not network"
.\venv\Scripts\ruff.exe check .
```

منبع باید BASELINES صریح، دارای سه ورودی سالم و فقط دوره توسعه باشد. برای مصرف اصلاحات جدید قیمت،
ابتدا فیچر توسعه و منبع BASELINES تازه بسازید؛ آرشیو قدیمی را بازنویسی نکنید. تاریخ‌های بعد از
۲۰۲۵-۰۳-۲۱ باز نمی‌شوند. خام نامعلوم یا شواهد اقتصادی ناکافی با عدد جایگزین پر نمی‌شود.

## اجرای ثابت و بازبینی

شناسه را از گزارش منبع و تعداد تلاش‌ها را از دفتر پژوهش بگیرید. عدد۶۷ فقط حداقل دامنه یک منبع۸×۴
به‌علاوه این خانواده۳۵حالتی است؛ کل تاریخ پروژه نیست. کامل‌نبودن دفتر باید صریح بماند.

```powershell
.\venv\Scripts\python.exe -X utf8 -m research.expectancy_run --source EXP-YYYY-MM-DD-BASELINES-ID --trials-attempted NUMBER --replications 20000 --workers 4
```

این متن placeholder است؛ شناسه و عدد واقعی لازم‌اند. حداقل، ترتیب برش و فرضیه‌ها را بر اساس نتیجه عوض نکنید.
گزینه `-X utf8` برای خروجی فارسی Windows، به‌ویژه هنگام هدایت به فایل یا ابزار دیگر، صریح است؛
Python۳٫۱۱ در بعضی محیط‌های pipe از cp1252 استفاده می‌کند و بدون این گزینه خطای کدگذاری می‌دهد.
DB موجود برای تطبیق منبع و ثبت پژوهش لازم است؛ در نبود DB، فرمان پایگاه خالی نمی‌سازد.
حساب آزمایش نقد فرضی صریح دارد؛ موجودی یا پروفایل واقعی مالک در این مسیر خوانده نمی‌شود.

`--workers` فقط زمان بندی محاسبات مستقل bootstrap را بین۱تا۴پردازش تغییر می‌دهد؛ ترتیب خروجی و بذر هر
مقایسه ثابت‌اند. مسیر ترتیبی با `--workers 1` در دسترس است و برابری دقیق آن با spawn آزمون شده است.
تعداد بازنمونه‌ها باید **پیش از نتیجه** با اندازه خانواده مقایسه متناسب انتخاب شود؛ ۲۰هزار نمونه برای
هر دفتر تلاش دلخواه کافی نیست. وضوح ناکافی در گزارش مانع است، نه مجوز حذف تلاش‌های قبلی.
پس از پایان هر برش، `fold-XX-checkpoint.json` اتمی ذخیره می‌شود و بازبین محتوای آن را هم دوباره محاسبه
می‌کند. اجرای قطع‌شده محفوظ می‌ماند؛ checkpoint مجوز انتخاب برش موفق یا ادامه با فرضیه تازه نیست.
اسکریپت شخصی فراخوان باید در Windows بدنه اجرا را زیر `if __name__ == '__main__':` نگه دارد تا فرزند
محاسبات، پژوهش یا DB را دوباره اجرا نکند. فرمان ماژولی بالا این حفاظت را دارد.

پس از پایان، شناسه از `data/research/latest-expectancy.json` قابل خواندن است:

```powershell
$run = (Get-Content .\data\research\latest-expectancy.json -Raw -Encoding UTF8 | ConvertFrom-Json).experiment_id
.\venv\Scripts\python.exe -X utf8 -m research.expectancy_run --review $run
```

بازبین فقط‌خواندنی است؛ برازش، تمام انتخاب‌ها و۳۵بازپخش هر برش و bootstrap را تکرار می‌کند، پس ممکن است
به‌اندازه اجرای پژوهش زمان ببرد. همه خروجی‌ها در آرشیو همان شناسه‌اند؛ شکست برنامه/پروتکل قبلی را پاک نمی‌کند.
جدول Markdown خلاصه است؛ JSON مخرج نامعلوم، عدم اجرا، هزینه، حقوق مصنوعی و خطای پیش‌بینی را نگه می‌دارد.
همه برش‌ها، فشار و کنترل‌ها را بررسی کنید؛ بهترین عدد به‌تنهایی معیار پذیرش نیست.

## بسته محدود بازار برای بازتولید بیرون از دستگاه

ارسال به سرویس یا شخص دیگر خودکار نیست. برای ساخت ZIP محلی:

```powershell
.\venv\Scripts\python.exe -X utf8 -m ops.research_bundle --source EXP-YYYY-MM-DD-BASELINES-ID
```

فقط سه Parquet بازار با ستون‌های مجاز و مشخصات محاسباتی محدود صادر می‌شوند؛ جدول حساب، رمز، DB،
کد نشست و metadata آزاد منبع صادر نمی‌شوند. مسیرهای محلی در مشخصات حذف شده‌اند. هش ورودی‌ها و هش
گزارش اصلی در manifest هستند، اما ثبت داخل ZIP **نمای محاسباتی تازه** است، نه کپی کامل ثبت اصلی.
پارتیشن‌های منشأ خام و نتیجه‌های مالی منبع حذف شده‌اند؛ این بسته برای بازتولید عددی است، نه ممیزی کامل
صحت/دسترسی تاریخی داده. ناشناس‌سازی عمومی یا اصالت بیرونی از آن استنتاج نمی‌شود. ZIP را پیش از ارسال بازبینی کنید.

قیمت‌گذاری حقوق واقعی شرکتی، تعرفه تاریخی، عضویت تاریخی و اجرای صف هنوز دروازه‌های جدا هستند.
این پژوهش و موفق‌شدن آزمون نرم‌افزاری، تضمین سود یا اجازه معامله واقعی ایجاد نمی‌کند.
