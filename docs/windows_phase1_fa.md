# شروع مرحلهٔ اول BRS روی Windows

این راهنما برای Windows و کاربر بدون تجربهٔ برنامه‌نویسی است. خروجی این مرحله: نصب قابل بررسی، آرشیو سهام و داشبورد؛ هنوز مدل سودده یا سیگنال تأییدشده نداریم. افق ۲–۳ روز یعنی **جلسهٔ معاملاتی**، نه روز تقویمی. بورس و فرابورس عادی فعال‌اند؛ بازار پایه و SME فعلاً خاموش‌اند و اضافه کردنشان تصمیم جدا می‌خواهد.

## ۱. ابزارهای لازم

| ابزار | کار آن | ضرورت |
|---|---|---|
| Git | دریافت پروژه و حفظ تاریخچه | لازم برای روش زیر |
| uv | ساخت Python 3.11 و نصب نسخه‌های قفل‌شده | لازم برای SETUP |
| VS Code | باز کردن پروژه و دیدن خطاها | پیشنهاد برای Vibe Coding |
| دستیار برنامه‌نویسی فعلی شما | تغییر کد با رعایت AGENTS.md، آزمون و بازبینی | یک دستیار کافی است |
| Streamlit، pytest، Ruff، SQLite و کتابخانه‌های داده | اجرا، آزمون و ذخیره‌سازی | خود SETUP آماده می‌کند |

فعلاً Docker، WSL، دیتابیس سرور، GPU و کلید هوش مصنوعی برای جمع‌آوری بازار لازم نیست. اتصال Jev برای تحلیل کدال اختیاری است. رمز کارگزاری یا کلید API را در چت نفرستید. این برنامه سفارش ثبت نمی‌کند.

از Start ویندوز **PowerShell** یا **Terminal** را باز کنید. سه فرمان زیر را **یکی‌یکی** اجرا کنید:

```powershell
winget install --id Git.Git -e --source winget
winget install --id astral-sh.uv -e --source winget
winget install --id Microsoft.VisualStudioCode -e --source winget
```

اگر نصب بودن ابزار اعلام شد مشکلی نیست. بعد از نصب، Terminal را ببندید و دوباره باز کنید:

```powershell
git --version
uv --version
```

اگر `winget` پیدا نشد، App Installer را از Microsoft Store نصب/به‌روز کنید. راهنمای رسمی نصب دستی: [Git](https://git-scm.com/install/windows)، [uv](https://docs.astral.sh/uv/getting-started/installation/)، [VS Code](https://code.visualstudio.com/docs/setup/windows). uv در صورت نبود Python 3.11 آن را هنگام ساخت محیط دریافت می‌کند؛ نصب Python جداگانه لازم نیست.

## ۲. دریافت نسخهٔ بازبینی‌شده، کنار نسخهٔ قبلی

برای حفظ پوشهٔ فعلی و دیتابیس شما، ابتدا یک پوشهٔ تازه می‌سازیم. این فرمان‌ها در PowerShell هستند:

```powershell
New-Item -ItemType Directory -Force C:\BRS
Set-Location C:\BRS
git clone --branch feature/brs-foundation-review https://github.com/CodeinScrubs/bourceir.git review
Set-Location C:\BRS\review
git status --short --branch
```

اگر پوشهٔ `review` از قبل وجود دارد و clone خطا داد، آن را حذف نکنید؛ از داخل همان پوشه خروجی `git status --short --branch` را بفرستید. شاخهٔ این راهنما مخصوص بازبینی است و با `master` فرق دارد.

اگر دریافت ZIP را ترجیح می‌دهید، [ZIP همین شاخه](https://github.com/CodeinScrubs/bourceir/archive/refs/heads/feature/brs-foundation-review.zip) را دانلود و استخراج کنید. Terminal را در پوشه‌ای باز کنید که `SETUP.bat` داخل آن است. ZIP تاریخچهٔ Git ندارد؛ روش clone برای ادامهٔ توسعه بهتر است.

## ۳. نصب و بررسی محلی

```powershell
.\SETUP.bat
```

پنج مرحله اجرا می‌شود: Python 3.11، نصب فایل قفل، Ruff و آزمون‌ها، فایل تنظیمات اختیاری، سپس دیتابیس و گزارش عیب‌یابی. محیط برنامه در `venv` است و با Python سایر برنامه‌های شما مخلوط نمی‌شود.

- پایان موفق باید عبارت `LOCAL SETUP PASSED` داشته باشد.
- خروجی «آزمایش شبکه انجام نشده» در این مرحله طبیعی است.
- اگر `SETUP FAILED` دیدید، **اولین خطا** را ارسال کنید. ادامهٔ اجباری یا حذف پوشهٔ data لازم نیست.
- اگر محیط قبلی Python دیگری دارد، پوشهٔ `venv` را به `venv-old` تغییر نام دهید و SETUP را دوباره اجرا کنید. `data` را تغییر ندهید.

گزارش قابل ارسال: `logs\doctor-local.json`. این فایل کلیدهای `.env` را نمی‌نویسد. بدون وجود خروجی موفق، آماده بودن رایانه شما تأیید نشده است.

## ۴. آزمایش فید از اینترنت خودتان

```powershell
.\CHECK_FEED.bat
```

این مرحله TSETMC را بررسی می‌کند؛ کلید Jev لازم ندارد. گزارش: `logs\doctor-feed.json`.

«پاسخ دریافت شد» فقط ارتباط و شکل کلی پاسخ را تأیید می‌کند. **تازگی، کامل بودن کل بازار و امکان معامله را ثابت نمی‌کند.** دیده‌بان گاهی فقط ساعت آخرین معامله را می‌دهد؛ بدون تاریخ کامل، وضعیت تازگی عمداً نامعلوم است.

اگر خطای شبکه گرفتید، سایت TSETMC را در مرورگر همان رایانه بررسی کنید. اگر از Proxifier/VPN استفاده می‌کنید، مسیر دامنه‌های TSETMC را با Direct مقایسه کنید. صرف timeout اثبات نمی‌کند علت حتماً VPN است. GitHub و دریافت بسته‌های Python هم باید از شبکهٔ شما قابل دسترس باشند.

## ۵. اولین دریافت کوچک

پیش از دریافت کل بازار، فقط پنج سهم پایلوت را دریافت کنید:

```powershell
.\venv\Scripts\python.exe brs.py update --symbols فولاد,خودرو,شپنا,وبملت,کگل --no-features
```

این فرمان تاریخچه، آمار حقیقی/حقوقی و یک بررسی کدال انجام می‌دهد. گزارش هر بخش جداست؛ ممکن است قیمت موفق و کدال ناموفق باشد. برنامه دادهٔ ساختگی برای پر کردن خطا نمی‌سازد. «ردیف‌های پردازش‌شده» لزوماً به معنی ردیف جدید نیست، چون تاریخچه می‌تواند اصلاح شود.

## ۶. دیدن داشبورد

```powershell
.\START.bat
```

مرورگر به `http://127.0.0.1:8501` می‌رود. پنجرهٔ اجرا را باز نگه دارید. صفحهٔ «بررسی نماد» باید دادهٔ واقعی سهم انتخابی را نشان دهد. دادهٔ خالی یا خانهٔ خالی، مقدار صفر یا سلامت فید محسوب نمی‌شود. واحد ستون‌ها را ببینید: ذخیره‌سازی ریال است؛ بعضی نماها با برچسب مشخص به میلیارد تومان تبدیل می‌شوند.

## ۷. یک مشاهده و بعد پایش زنده

در ساعت بازار، ابتدا یک چرخه:

```powershell
.\venv\Scripts\python.exe brs.py live --symbols فولاد,خودرو,شپنا,وبملت,کگل --cycles 1
```

برای ادامهٔ پایش، `--cycles 1` را حذف کنید. با `Ctrl+C` متوقف می‌شود. پیش‌فرض تقویم، شنبه تا چهارشنبه و ۹ تا ۱۲:۳۰ تهران است؛ تعطیلات و تغییرات مقررات نیاز به تأیید/ثبت دارند. تعطیلی ثبت‌شده در `market_calendar` در CLI رعایت می‌شود. فاصلهٔ ۳۰ ثانیه یک هدف است؛ اگر دریافت طولانی شود، تأخیر چرخه لاگ می‌شود.

فقط برای عیب‌یابی خارج ساعت بازار می‌توانید `--force --cycles 1` بدهید؛ این کار دادهٔ خارج ساعت را به دادهٔ زندهٔ قابل معامله تبدیل نمی‌کند.

اسنپ‌شات واقعاً بدون تغییر دوباره ذخیره نمی‌شود؛ تغییر در هر یک از پنج مظنه یا آمار ثبت‌شده باید حفظ شود. شمار اسنپ‌شات به‌تنهایی معیار پوشش همهٔ نوبت‌های دریافت نیست؛ `collection_log.details_json` شمار بدون‌تغییرها را نگه می‌دارد.

## ۸. کل بازار و ویژگی‌ها، پس از موفق شدن پایلوت

```powershell
.\venv\Scripts\python.exe brs.py update --full
```

دریافت کامل بسته به شبکه و نمادها ممکن است طولانی باشد؛ عدد ثابت ۴۵ دقیقه تضمین نیست. ساخت ویژگی فقط بعد از تکمیل موفق مراحل انجام می‌شود. اگر یک بخش شکست خورد، ابتدا همان خطا بررسی شود.

برای ساخت مستقل ویژگی پس از دریافت کافی:

```powershell
.\venv\Scripts\python.exe brs.py features
```

خروجی در `data\features\daily-v2\<شناسهٔ واقعی اجرا>` قرار می‌گیرد؛ شناسه توسط برنامه ساخته می‌شود. این عبارت نمونهٔ ساختار مسیر است، فرمانی برای کپی کردن نیست. هر اجرا ورودی‌ها، خروجی و manifest خودش را دارد. نسخهٔ قدیمی حذف نمی‌شود. این داده هنوز «بازسازی پژوهشی گذشته» است و مشکل نمادهای حذف‌شده و زمان واقعی انتشار تاریخچه حل کامل نشده است.

## ۹. اگر دیتابیس قبلی دارید

پوشهٔ جدید ابتدا روی دیتابیس خالی آزموده شود. برای ارتقای آرشیو قبلی، همهٔ پنجره‌های جمع‌آوری و داشبورد قبلی را ببندید. پوشهٔ `data` قبلی را یک‌جا به محل جداگانه کپی کنید. اگر فایل‌های `brs.db-wal` و `brs.db-shm` وجود دارند، از آنها چشم‌پوشی نکنید؛ نسخهٔ سالمِ کامل لازم است.

سپس نسخهٔ کپی‌شدهٔ دیتابیس را در پوشهٔ `data` نسخهٔ جدید بگذارید و SETUP را اجرا کنید. برنامه پیش از مایگریشن روی دیتابیس موجود پشتیبان می‌گیرد. خطای مایگریشن باید بررسی شود؛ فایل‌های مایگریشن یا شماره نسخه‌ها را دستی عوض نکنید.

دادهٔ قدیمی منشأ خام تأییدنشده می‌گیرد و وارد ساخت ویژگی جدید نمی‌شود. `update --full` آن را از منبع دوباره دریافت می‌کند. اصلاحات از مایگریشن 007 به بعد بایگانی می‌شوند؛ چیزی دربارهٔ زمان واقعی دسترسی به داده‌های قبل از این ثبت اثبات نمی‌شود.

پشتیبان دستی:

```powershell
.\venv\Scripts\python.exe brs.py backup --keep 5
```

پشتیبان در `data\backups` است. فایل‌های ویژگی جدا هستند؛ برای نگهداری یک آزمایش باید پوشهٔ اجرای ویژگی و نسخهٔ کد آن هم محفوظ بماند.

## ۱۰. روش ادامهٔ Vibe Coding

پوشهٔ پروژه را در VS Code باز کنید: `code .`. از دستیار فعلی خود استفاده کنید و متن زیر را ابتدای کار بدهید:

> AGENTS.md و docs/foundation_review_fa.md را بخوان. هدف این تغییر را محدود نگه دار، روی شاخهٔ feature کار کن، یک آزمون برای خطای واقعی بنویس، همهٔ آزمون‌های آفلاین و Ruff را اجرا کن و تغییر و محدودیتش را به فارسی توضیح بده. دادهٔ ساختگی وارد data نکن. نتیجهٔ مالی را بدون ارزیابی خارج از نمونه قابل اتکا اعلام نکن.

برای بررسی مستقل هر تغییر:

```powershell
.\venv\Scripts\ruff.exe check .
.\venv\Scripts\python.exe -m pytest -m "not network"
git diff --stat
```

**گام بعدی مشترک:** فایل `doctor-feed.json` و نتیجهٔ اولین دریافت پنج نماد را بفرستید. پس از آن، پوشش چند جلسهٔ واقعی را اندازه می‌گیریم؛ سپس سراغ برچسب بازده خالص ۲ و ۳ جلسه‌ای، استراتژی پایه و مقایسهٔ خارج از نمونه می‌رویم. انتخاب مدل قبل از این مرحله ارزش کمتری از تأیید داده دارد.
