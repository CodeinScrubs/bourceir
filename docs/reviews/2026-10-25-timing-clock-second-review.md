# TimingClock 2.1.1 reviews: adjudication and 2.1.2 fixes

Reviewed and tested on 2026-10-25 with Windows PowerShell 5.1 / .NET Framework on x64 Windows. This is the generic local desktop timing tool. All physical input tests target owned harmless fixture windows. No broker orders, account modifications or financial test transactions were used.

## Findings and evidence boundary

The reviews found additional real faults. An identical, self-contained 11-case harness fails all 11 cases on the preserved, unchanged 2.1.1 sources and passes all 11 on 2.1.2. These are targeted reproductions, not an exhaustive bug count. A separate hardening suite covers 17 groups, including heartbeat expiry inside validation, rollback back into a legitimate wait, shutdown after commitment, timer creation failure, lease restoration, and notification/disposal contracts.

The old 2.1.1 archive remains unchanged: SHA-256 `0bf583fe379f2019f00cc08888589148b672bf9921b53229354c90a3d2f4b521`. All 65 manifested files and the archive CRC were rechecked. Integrity is not publisher authentication. The test receipts and manifests are locally generated and unsigned.

The review attachments were read as proposals, not executable instructions. No pasted patches were executed. ## Confirmed defects and changes

| Claim / source | Decision and final behavior |
| --- | --- |
| Optional/null dispatcher commit, R1 N1 | Confirmed. `tryCommit` is mandatory and null is rejected before input. Shipped scheduling already passed a gate; the callable helper could bypass it. Do not mistake this helper defect for proof that a particular live attempt bypassed cancellation. |
| UI health can expire during target capture, R3 F1 | Confirmed. The shipped UI passes a sealed atomic heartbeat/failure/generation monitor. It is checked after capture, at the owned commit gate and near native dispatch. The old arbitrary callback remains before final capture only. Tests cover failure/generation and real heartbeat-age expiry without invoking user code after capture. |
| Preemption plus wall rollback after final target query, R2 B4 | Confirmed with the same baseline/fixed harness. The owned gate rechecks monotonic/wall continuity, cumulative drift, freshness, held keys and Escape before the commitment CAS. The native wrapper also rechecks wall deadline and UI health. A final software-check-to-native-call race remains; this is not a hard real-time atomic clock/input operation. |
| Send timestamps overstate measurement, R3 F2 | Confirmed and corrected. The old `SendStarted` reused a pre-commit deadline sample. The old return timestamp could include release cleanup. Version 2.1.2 records gate, managed queue entry/return, pre-native check, independent adjacent native entry/return samples, monotonic native duration, release timing and dispatch completion separately. Native error is captured immediately after `SendInput`, before another native API can overwrite it. Synthetic queues never receive invented native timestamps. |
| Prepared disposal invokes a blocking callback synchronously, R3 F5 / R1 N11 | Confirmed. Result publication/resource cleanup are separate from ThreadPool notification. Start failure calls Finish outside `startGate`. Prepared cancellation/disposal no longer waits on an arbitrary completion callback. Pending notification and notification error are observable. This does not make every possible native IPC call interruptible. |
| Final result can be lost during ordinary close, R3 F6 | Confirmed. Closing independently persists an already published result even when the queued UI callback has not run. Deduplication prevents a second result entry. An unfinished committed worker produces `shutdown_pending`, explicit phase, cancellation status, unresolved outcome and null input count. Forced termination/power loss can still interrupt disk writes. |
| Stale `DisposeTimedOut`, R1 N8 / R3 F11 | Confirmed. Current timeout clears after a later successful join; `EverDisposeTimedOut` retains historical evidence. A blocked notification is distinguished from a live worker. |
| Visible/topmost clock obstructs point picker, R3 F4 | Confirmed. Picker minimizes during capture, restores on completion/cancellation/stall/lifecycle exit, and chooses a non-covering placement. If no placement exists, selection fails closed. The physical UI fixture begins with the visible topmost clock over its own target, then validates the restored selection. |
| Drive-root canonicalization, R1 N7 / R2 B2 | Confirmed. C# and PowerShell preserve root separators and strict descendant containment. Read-only drive-root checks create nothing at drive root. Production launcher source snapshots, staged/final binaries, receipts and launch paths consistently use the checked helpers. |
| Future `LastInput` tick becomes a huge quiet interval, R2 B8 | Confirmed. Unsigned wrap is accepted only for a plausible non-future age (at most Int32.MaxValue). Tests retain ordinary tick rollover behavior and reject a one-tick-future input timestamp. |
| Wrong-thread GUI mutex disposal, R3 F8 | Confirmed. ApplicationLease enforces owner-thread release and preserves recovery by that owner. The original production GUI normally disposed on its UI thread; the generic resource contract still needed enforcement. |
| PlanLease release error skips handle disposal, R3 F12 | Confirmed hardening. Closing is attempted even if release fails. Both errors survive as an aggregate and appear by exception type in cleanup diagnostics. Disposal is idempotent; no raw exception message containing account information is added to a public log. |
| Owned custom Font lifetime, R2 B7 | Confirmed on Windows with the baseline reproduction. Owned fonts are tracked and disposed with the form. The fixed reproduction passes. |
| Partial final snapshot consistency, R3 F9 | Valid. Capture now rereads client geometry, root/leaf DPI, virtual desktop, monitor/layout and mouse settings in addition to identity/class/window bounds. A real owned window changes only its client-area style during capture and is rejected. Validation retains these consistency checks. |
| Final checked `wait` mislabeled clock change, R3 F10 / R1 N13 | Confirmed. A small permitted rollback before the final due check resumes waiting; it cannot send early. Automatic NextTarget skips a local DST gap/fold within a bounded search. Explicit invalid/ambiguous dates still reject. Tehran currently has no DST, but the generic timezone contract is tested. |
| Missing timer creation error / silent coarse fallback, R1 N17 / R3 F3 | Valid. Production WindowsClickEnvironment requires an acquired high-resolution timer before arming. NULL creation captures native error and refuses scheduling. An internal wait fallback remains for a testable helper; it is not a silently degraded production path. A later timer-arm failure aborts. |
| Desktop span exceeds absolute-coordinate representation, R1 N18 | Valid. The plan rejects width/height above 65536 before dispatch. Existing per-coordinate checks remain. |
| Inconsistent wait-array publication, R1 N14 | Valid hardening, not a reproduced production race. Cancel handle and handle array are published as one immutable holder. The timer still has a single-worker contract; concurrent independent rearming is not newly supported. |
| Concurrent diagnostic append, R1 N16 | Valid hardening, not a demonstrated lost production append. Cleanup/timing messages are appended under a lock; concurrent fixture checks retain all messages. |

## Claims requiring qualification or rejected fixes

| Claim / proposed change | Adjudication |
| --- | --- |
| A cancelled schedule must never have LatenessMs, R2 B3 | Incorrect as a general rule. A real gate check may occur before cancellation wins. Keep that signed sample and label it `deadline_gate_sample`; do not invent SendStarted or native fields. A regression verifies zero input and a retained labelled decision sample. |
| Every guard rejection needs DispatchCheckAt, R1 N15 | A target/input guard may reject before the dispatch gate runs. Leaving that gate timestamp null is honest. `LastTimingCheckAt` provides a separate actual observed time; rejected deadlines retain their own precise signed gate values. |
| `Cancel()` during RehearsalObserving must rewrite outcome, R1 N9 | The documented boolean guarantees no subsequent native input. During pure rehearsal that guarantee is already satisfied; the observation remains `rehearsal_due`. Added an in-flight barrier test and distinct UI wording. It does not claim a native click was cancelled. |
| Blocked native target query needs forceful recovery/new schedule, R2 B5 | A worker blocked in native IPC cannot safely be killed and replaced while its eventual input is uncertain. Preserve the pending state, reject new scheduling and provide bounded close with explicit unresolved outcome. No unsafe thread abort or speculative retry was added. |
| Approximately 65 syscalls/9 allocations caused a measured delay; drop final consistency checks, R2 B6 | Exact counts and the causal explanation were not measured on the supplied live attempt. Fixed duplicate WindowFromPoint retrieval and added guard-duration telemetry. The proposed shortcut would weaken validation and is rejected. No universal 3.5 ms spin lead or pre-dispatch early firing was adopted without target-machine evidence. |
| 100 ms default violates guaranteed millisecond delivery, R3 F3 | The display supports millisecond targets; it never made Windows hard real-time. The explicit maximum-lateness setting stays 100 ms by default. Choosing 1–5 ms rejects more late local samples and can miss an action; it cannot guarantee target receipt within that time. Required high-resolution timer capability now fails closed. |
| Timer flag 0x2 is manual reset | False; the reviewer corrected this in the second round. Microsoft defines high-resolution as 0x2 and manual-reset as 0x1. No flag fix or blanket timeBeginPeriod call is warranted. |
| There is no ambiguity latch anywhere, R1 latch wording | False for the GUI: ClockWindow.failed already disables further scheduling after ambiguous dispatch or audit failure. The generic ClickSchedule API does not impose a process-wide circuit breaker. Documentation now states this scope explicitly. |
| Symlink/junction workspaces must start; reparse cache should automatically rebuild, R1 N4/N6 | These are deliberate supported-path/security policies. Ordinary local non-reparse paths are supported; redirected roots/caches fail closed. Do not follow or rebuild through a rejected redirect. Not every subst drive is a reparse point; the review's blanket equivalence is unsupported. Same-user concurrent hostile path replacement is outside this local integrity check. |
| `private` means a new confidential ACL, R3 F7 | Correct documentation concern. The folder is local and Git-excluded, with inherited Windows ACLs. No promise of cross-user confidentiality and no silent ACL rewrite. |
| Published previous review hash is wrong, R1 N3 | Recomputed all four old attachment hashes: every value matches the exact supplied Pasted text.txt bytes. An external REVIEW.md with edits/wrappers has different bytes. Clarified the hash scope instead of replacing a correct hash with a different document's hash. |
| 2.1.1 final sidecars do not exist, R1 N2 | They do exist locally as ZIP-stem `.validation.json` and `.checks.txt`, bound to the unchanged 65-file archive. They were not inside the ZIP forwarded to the reviewers: a real delivery gap. The new outer bundle includes the inner project ZIP and its validation/check/hash sidecars together. |
| Native INPUT layout is 40/28 bytes; error=0 proves destination accepted | Layout assertions are correct. A returned count of three says three packets entered the Windows input stream. It does not prove destination processing, a broker's business acceptance or any exchange time/queue position. |
| Three success trials prove robust percentiles/worst case or beat every competitor | Unsupported. Retained per-trial values and workload limits; no percentile claim. The new source-bound x64 trials are ordinary-desktop observations. Feature breadth, operational safety and timing guarantees are different comparisons. |

## Validation and reporting

The original baseline and failed runs are retained; they are not relabeled as passing evidence. The 11-case baseline/fixed reports bind the same test-harness bytes to different production source hashes. Fixed tests include 32 fault groups, 8 deadline groups, 14 refinements, 16 prior-review groups, 11 baseline reproductions and 17 hardening groups. Clock parsing/logic, launcher behavior, isolated builds, real junction rejection and read-only platform assertions have separate reports.

Reports now carry explicit totals/failures/pass state and timestamp/version metadata where appropriate. Build/path reports preserve an outer run error rather than declaring success solely because completed checks passed. The platform probe now makes three capability assertions; it remains read-only. Snapshot mutation tests assert exact reasons. UI rendering is manually inspected for legibility; the screenshot is not an automated pixel or every-DPI test. Mock clocks/sinks are explicitly identified and supplemented with owned real-window/client-change and native input fixtures.

The final native click fixture passed three success trials and six negative scenarios. Success native-boundary lateness was 9.9773, 0.6603 and 0.6651 ms; target MouseDown lateness was 20.5494, 13.0400 and 8.1903 ms. Each success received exactly one down/up/click. Negative scenarios received zero clicks. The full physical UI workflow passed, including visible picker restore, Escape, lifecycle signals, UI freeze and failed-audit latch. A preceding no-input UI rehearsal rejected `recent_input` while the desktop was active; its failed receipt is preserved and is not counted as a pass.

These tests do not exercise every display edge/DPI/monitor configuration, 32-bit native delivery, real lock/sleep/hotplug, elevated targets, actual OS partial SendInput results, long-wait loaded-machine tails, remote sessions or business semantics. Existing synthetic fault cases are not physical evidence for those scenarios. Do not weaken guards to make a live test green. No promise of 1 ms destination receipt, future order acceptance or queue rank follows from this release.

The review ZIP includes exact source, test drivers, this adjudication, a reference executable bound to its source snapshots and sanitized fixture-only evidence. Its manifest is checked after extraction and safe checks run against the sealed inner ZIP. Validation sidecars live outside that inner ZIP to avoid self-reference; the outer bundle contains them. Account captures, real-trade journals, credentials and raw private review attachments are excluded.

## Authoritative API references

- [CreateWaitableTimerExW](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createwaitabletimerexw): high-resolution flag, supported OS and NULL/error behavior.
- [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput): returned input count and UIPI limits; last error alone cannot identify UIPI blocking.
- [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo): tick values are not guaranteed to increase monotonically.
- [Mutexes](https://learn.microsoft.com/en-us/dotnet/standard/threading/mutexes): thread-owned release.
- [SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate): thread-scoped awake request and failure behavior; no guarantee against user-triggered sleep.
