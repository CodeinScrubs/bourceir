# پوشش اجرای CI برای شاخه‌های پژوهشی

## مسئله

گردش‌کار BRS CI فقط روی push به `master` و شاخه‌های `feature/**` اجرا می‌شد، در حالی که شاخه‌های پژوهشی پروژه با پیشوند `feat/` ساخته می‌شوند. در نتیجه، push به شاخه‌ای مانند `feat/annual-multibagger-research` به‌تنهایی آزمون‌های Python 3.11، Ruff و بررسی‌های ویندوز را اجرا نمی‌کرد. برای PR خارجی نیز اجرای workflow ممکن است به تأیید مالک مخزن نیاز داشته باشد؛ تغییر الگوی شاخه این محدودیت امنیتی GitHub را دور نمی‌زند.

## تغییر

`.github/workflows/tests.yml` اکنون `feat/**` را نیز در رویداد `push` می‌پذیرد. این تغییر هیچ سطح دسترسی نوشتن جدیدی به workflow نمی‌دهد و هیچ داده بازار، مدل، پارامتر معاملاتی یا سیگنال زنده‌ای را تغییر نمی‌دهد.

## اعتبارسنجی و محدودیت

فایل YAML و تغییرات را باید با CI واقعی در GitHub بررسی کرد. صرفاً افزودن الگوی شاخه، اثبات نمی‌کند که workflow اجرا می‌شود: سیاست مخزن، تنظیمات Actions و تأیید اجرای workflow از fork همچنان تعیین‌کننده‌اند. پس از push این شاخه، وضعیت run و jobها را در Actions بررسی کنید. تا زمانی که jobهای Linux و Windows اجرا نشده و تست‌ها/Ruff موفق نشده‌اند، PRهای پژوهشی باید draft باقی بمانند.
